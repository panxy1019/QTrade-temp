# 历史状态采集队列与覆盖验收

## 修复的问题

原调度只扫描股票列表前 N 股，部分失败就保持 N。集群在 40 股范围内已完成
36 股，4 股反复返回供应商错误 10002007，导致其余 950 股尚未尝试。
这不是完整股票池缺失的唯一原因，但它阻塞了现有 990 股的状态回填。

新调度复用现有 BaoStock 会话锁、主表缓存、状态文件、原子写入和来源归档。
没有新增数据供应商、撮合引擎、交易网关或运行权限。

## 两条采集队列

每批分别选择最多 20 股从未尝试的股票，以及最多 5 股到期重试的股票。
股票范围绑定冻结行情的 `dataset.json`；不会从页面接受任意股票代码或文件路径。
成功股票必须有校验通过的原始状态文件。已有成功记录却丢失来源文件时拒绝执行，
不能靠进度账本补造成功。

单股开始查询前，先将 RUNNING、尝试次数和下次重试时刻写入
`pit-repair/symbol-attempts.json`。失败保留异常类型及有限的供应商错误码，
不保存异常消息或凭据。单股退避依次为 30、60、120、240、360 分钟，之后
保持最长六小时。进程被终止的 RUNNING 项目仍是未解决状态，不能计入覆盖。

尚有未尝试或已到期重试股票时，下一批最早一分钟后启动。只剩等待重试的股票时，
等待最早到期时刻；整段来源或进程失败则保留全局退避。
全部目标都有来源文件后按六小时间隔检查。
每个子进程仍最多运行 30 分钟，剩余存储必须大于 100 GiB，供应商会话继续串行。

## 进度语义与兼容

- 来源只完成部分时始终是 PARTIAL，即使当前子进程退出码为 0。
- 覆盖报告同时列出完成、未解决、尚未尝试、到期及等待重试数量。
- 已知未解决错误会继续出现在后续覆盖报告中；新批次成功不会隐藏旧错误。
- 调度只接受本次子进程开始后生成、校验和正确、范围及计数一致的回执。
  旧 COMPLETE、伪造 COMPLETE 或损坏回执不能跳过失败退避。
- 迁移前的 `next-pass.json` 保存在内容哈希命名的 `legacy-next-pass-*.json` 中。
  原始主表和状态文件不重写；新覆盖报告获得新身份。
- 单次人工命令仍可指定前 N 股；监督服务采用全输入范围内的分批队列。
  本轮输入范围为 990 股，目标数量不等于已完成数量。

新实验会固定提交时的覆盖报告及原始文件。已归档的 36 股来源实验仍保留其
原身份和结果，后续覆盖增长不会回写这些实验，也不触发自动重训。

## 复现

```bash
PYTHONPATH=src python -m pytest tests/test_pit_source.py \
  tests/test_pit_collection_queue.py tests/test_source_constraints.py
python -m ruff check .

# 单次有界采集：最多20股未尝试股票 + 5股到期重试股票
PYTHONPATH=src python -m scripts.collect_pit_evidence \
  --base "$BASE" --maximum 990 --batch-size 20

# 监督服务；保留共享会话锁、独占租约和子进程回收
PYTHONPATH=src python -m scripts.run_pit_repair --base "$BASE"
```

Windows 不支持本项目现有的目录 fsync 持久化路径，因此完整持久化验收在
Linux 集群执行。相关本地测试用假供应商验证调度与错误恢复，不访问网络。
本轮集群完整测试、实际覆盖增长和发布证据将在验收后补充。

## 仍未解决

这些原始状态是现在收到的历史回填，不是过去保存的时点快照。
即使全部 990 股都采集成功，当前流动性样本仍有幸存者与筛选偏差，
退市股票价格、历史成员及状态的实际可得时间仍需独立核验。
精确涨跌停、上市初期例外、公司行为和交收约束也不能由采集成功推出。
所有结果保持 `NOT_ELIGIBLE`，`LIVE_TRADING_ENABLED=false`。
