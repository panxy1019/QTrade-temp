# 09｜数据、PIT、交易约束与证据身份

[返回学习目录](README.md)

## 1. 一根 Bar 里有什么

OHLCV 分别是开、高、低、收、成交量。成交额 amount 通常以人民币金额表示；volume 可能是股或手，必须按来源认证。二者单位对应后，才可以计算：

    VWAP = amount / volume_in_shares

分钟 Bar 是区间聚合，不能还原逐笔顺序、挂单深度或开盘排队。日 Bar 的最高和最低也不能告诉你先触及哪个价格。

## 2. 原始价格、复权价格与总收益

股票分红、送转、配股会改变名义价格或股数。复权希望减少公司行为造成的机械价格断点。

- 原始价格适合与真实成交价格、金额和价格限制核对。
- 前复权通常以较新价格尺度调整过去，后来事件可能改变历史序列。
- 后复权按历史公司行为累计调整，同样需要核对事件、生效日、供应商修订与现金处理。

“已经复权”不等于“完全 PIT”或“完整分红再投资账户”。价格调整、现金分红、股数变化、基准总收益需要一体核对。

当前 Qlib 使用供应商生效日后复权乘数 H，首日归一化常量 C：

    factor = H / C
    adjusted_price = raw_price × factor
    adjusted_volume = raw_volume / factor
    adjusted_vwap = raw_vwap × factor

这样 adjusted_vwap×adjusted_volume 等于原始成交额，close/factor 可以恢复 raw close。它保证转换内部一致，不意味着供应商事件已经与权威公司行为库逐条对账。

## 3. PIT 的含义

Point-in-Time：在历史决策时刻，只允许使用当时可获得的信息。

教学例子：2025 年年报在 2026 年 4 月发布，即使写着 2025-12-31，也不能供 2025 年 12 月选股使用。公告修订后还要保留旧版本，不能将修订答案回填为最初可知信息。

至少分清三个时间：

| 时间 | 含义 |
|---|---|
| 有效/生效时间 | 状态或公司行为从何时适用 |
| 市场首次可用时间 | 投资者最早何时能知道 |
| 采集/入库时间 | 我们何时取得并保存这个版本 |

今天补采历史资料并非天然违规；关键是能否可靠重建当时首次可见内容，并披露后来修订。不能简单要求“今天下载的数据都不能回测”，也不能因为事件日期很早就认为它当时已知。

## 4. 幸存者与筛选偏差

今天仍存在、成交活跃的股票，不等于 2018 年当时可以买的完整集合。退市、长期停牌、后来冷清的股票可能被遗漏，新股的历史也不存在。

当前原始 1000 股按样本末期的流动性、存续和历史长度筛选；适配后 990 股。即使扩至今天全部股票，也需要补历史退市证券与动态准入，才能减少该偏差。

动态 Top1000 应使用各历史日期以前已完成数据选择，不是把今天 Top1000 固定回投。当前样本不能被叫作中证 1000 历史成分。

## 5. 数据缺失不是停牌证明

缺 Bar 可能是停牌、上市前、退市后、来源漏数、采集失败、时间格式或历史修订。需要分类原因；“缺失即不可成交”是执行保护，不能当作拥有完整历史停牌表。

禁止用前向填充价格创造有交易的日子。估值延用上次价格与“允许以该价格成交”也是不同动作。退市持仓的最终处置不能用静默删除来抹掉损失。

## 6. 交易约束为何影响因子结论

预测最强的股票可能是涨停买不到、跌停卖不出、小额交易最低费很高，或成交量不足。研究至少需要：

- 按日期生效的板块、ST 与涨跌停状态。
- 停复牌、上市与退市阶段规则。
- 可卖数量、结算限制及最小交易数量。
- 原始价格、除权参考和价格精度。
- 成交量、金额、参与率与成本模型。

本手册不列一张永远固定的全市场规则表；制度有板块和日期差异，应使用对应时期交易所规则。当前 4.5% 开盘跳空代理及统一 100 股约束，只是已明确披露的基线近似。

## 7. “因果回测”与“无泄漏研究”

收盘信号在下一 Bar 开盘执行，解决的是基本事件先后顺序。若股票池按未来筛选、财务字段事后修订、复权因子回填未来、模型选参反复查看测试，研究仍可能泄漏。

因此代码时序因果只是必要检查之一，不是“全部历史输入已时点认证”的同义词。

## 8. 当前数据、发布与实验是三只钟

    数据时钟：行情覆盖到哪个已完成交易日/分钟
    发布时钟：只读快照最后何时生成
    实验时钟：某次运行的数据截止与评价截止

当前维护/发布约每 5 分钟检查，网页每 60 秒核对，交易时段观测约 15 分钟采集。它不是逐笔实时行情。完整日数据与盘中未结束 Bar 分开使用。

周日 2026-10-25 的最近完整交易日为 10-23；日线停在 10-23 可以正常。IC 截至 10-21 又可能是未来标签尚未成熟，不是采集故障。

固定 8 月报告仍停在 8 月则是实验身份；如果用户期待最新研究，需要另建运行，不能改标题或拼接曲线冒充旧规则已经持续有效。

## 9. 新鲜度状态如何阅读

FRESH 表示符合当前通道的新鲜规则，不保证多年历史无缺口。STALE 表示发布或源数据超时，需要查看具体时钟。FAILED 表示某次获取/校验失败，也可能保留前次不可变证据，但界面不能把它伪装成新成功。

当前交易日历有效至 2026-12-31；日历本身也是需要维护的输入。发布年龄阈值约 20 分钟与源数据容许延迟是不同条件。

## 10. 哈希、manifest、签名和血缘

SHA256 将内容映射为摘要。内容变化，摘要通常随之变化；比较摘要可以发现与预期版本不一致，但不能从摘要还原内容，也不能验证经济逻辑。

| 对象 | 绑定什么 |
|---|---|
| dataset checksum | 数据文件内容 |
| data_version | 人可读/结构化的数据版本身份 |
| spec_hash | 运行或行为规格 |
| result_hash / preview_hash | 规范化响应或结果 |
| record_hash | 含身份与结果引用的实验记录 |
| artifact manifest | 文件路径、大小、哈希等清单 |
| Git commit | 源码快照 |
| lineage | 因子→策略、父策略→子策略等明确关系 |

页面部分“签名报告”文案采用内容哈希封装；不能仅凭这个词就理解成权威机构或公钥数字签名认证了行情真实性。

行为规格哈希可能只覆盖开平仓/成本，不等于完整注册 StrategySpec；看完数据后生成哈希，也不能证明看之前已冻结。

## 11. 完整 ExperimentRunSpec 的 13 个字段

当前 runner 定义：

| 字段 | 用途 |
|---|---|
| experiment_id | 运行身份 |
| strategy_id | 关联策略身份 |
| git_commit | 源码版本 |
| data_version | 数据快照 |
| universe | 标的清单 |
| factor_set | 因子清单 |
| label | 预测/评价目标 |
| split | 训练、验证、测试划分 |
| model | 模型身份 |
| parameters | 参数 |
| cost_model_id | 成本口径身份 |
| transaction_cost | 成本参数 |
| seed | 随机种子 |

网页“生成哈希化运行规格草案”只构造这些字段与哈希；“按该哈希运行”再绑定结果。它们当前不等于写入不可变实验仓库、完成泄漏审查或获得新证据。

## 12. 正式归档保存什么

应保存输入清单、完整规格、源代码/提交、环境、模型、预测、标签、逐日净值、持仓/交易及成本、基准与校验清单。失败尝试也应记录。

重复运行同 ID 同规格应能核对一致；同 ID 不同规格应拒绝或新建版本。修复数据和执行规则后要重跑整组对照，不能只更新最赚钱者。

Qlib 目前已经有完整独立归档；旧 11 条候选部分原始规格不足以独立复算，也如实保留这个限制。

## 13. GitHub、集群与 Vercel 的关系

代码 main 提交可触发 Vercel 构建；集群负责采集、特征、训练和完整产物。网页读取小型只读数据发布。上传因子文件只改变代码，不会自然得到已验证研究结果。

一条完整新增因子路径是：定义并测试数据时钟→注册配置→冻结实验→集群运行→校验归档→发布摘要→网页展示。代码部署、数据刷新和模型训练应分别有状态。

文档中的完整原始数据不应推入代码 Git；网页 JSON 也不应无限承担全量行情数据库功能。

## 14. 研究结论的升级条件

数据修复、独立研究、统一对照、前向观察、注册和运行准备各解决不同问题。当前历史结果先保持诊断身份；真正改进证据后再明确升级，不应靠 UI 按钮改一个状态字符串。
