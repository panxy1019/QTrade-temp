## 1. 先把量化研究想成一条流水线

假设你想验证“最近跌得多的股票，接下来会反弹”。

你先取得价格，把过去五天涨跌幅取负，得到反转因子；每天按这个值给股票排序；选前 50 只，规定何时买入、何时卖出、花多少钱；最后在历史行情上模拟，计算成本后的资金变化。

这中间存在六个不同问题：

| 层次 | 问题 | 网站里的对应物 |
|---|---|---|
| 数据 | 当时有哪些股票？价格与公告何时可知？ | 数据中心、行情中心、数据身份 |
| 因子 | 什么信息可能解释未来收益？ | 因子定义目录、因子搜索、分钟开仓规则 |
| 模型/信号 | 如何把信息转成分数？ | 手写排序、LightGBM 预测、方向分数 |
| 组合策略 | 选谁、持有多少、多久调整？ | 策略模板、Top K、现金预留、TopkDropout |
| 回测 | 在成本和成交条件下结果如何？ | 净值、回撤、交易、行业和时间拆分 |
| 治理与运行 | 证据够不够？能否进入下一阶段？ | 顺序门、预注册、注册前审查、PAPER 准入 |

好看的曲线处于流水线后端。如果前端使用了未来信息，后端计算再精确也不能修复研究偏差。

    数据与时点 → 因子 → 模型/规则分数 → 组合目标 → 成交与成本 → 结果
         └──────────────── 每层均需版本、质量与证据检查 ────────────────┘

## 2. 网站各页面的分工

| 页面 | 应该用它做什么 | 常见误读 |
|---|---|---|
| 总览 | 看平台级状态与数据提示 | 把“系统正常”当作“策略盈利可靠” |
| 行情中心 | 查看当前数据和冻结历史档案 | 把数据预览范围当作集群全部库存 |
| 策略中心 | 浏览已实现模板、旧实验候选 | 把候选表理解成正在运行的策略列表 |
| 策略研究 | 检验因子、解释稳健性与准入边界 | 把多个报告视为同一策略的连续进度 |
| 实验中心 | 查看实验身份、分割和持久化结果 | 认为每条实验已成为注册策略 |
| 回测分析 | 用参数即时重算，或读固定历史曲线 | 把当前数据预览当成正式冻结实验 |
| 模拟交易/持仓/委托与成交 | 观察运行与执行链路的状态 | 认为研究页点击按钮就会下单 |
| 风控中心 | 查看风险限制、拒绝与恢复状态 | 认为风险门能弥补预测和数据偏差 |
| 数据中心/系统监控 | 看输入、连通性、新鲜度与运行状态 | 把“发布新鲜”当成“每份报告都刚重跑” |

本套文档详细覆盖前两个研究页面，并补充理解它们所必需的回测与数据概念；其他页面的全部运维功能不在本次逐按钮核对范围。

## 3. 当前平台实际是几套东西并存

### 3.1 旧 QTrade 日频研究

以 ETF 为主，有动量、趋势、目标波动率和横截面排序实现。它保留了 11 个旧实验候选及因子搜索、鲁棒性等报告。

### 3.2 旧分钟研究

有 75 股、15 行业的原生五分钟冻结数据，支持开盘方向规则、T+1 退出、成本和统计检验。120 日长期复核报告和页面可调工作台也属于这条线。

### 3.3 当前数据通道

采集与质量检查在集群，网页读取小型只读发布。当前行情和参数化回测可以跟随数据版本推进；旧固定报告保留原始日期。

### 3.4 新 Qlib 研究

复用采集与归档，使用 Qlib 计算 Alpha158、训练 LightGBM、生成预测和组合回测。这个结果以独立面板展示，目前没有把所有旧模板和报告统一迁入 Qlib。

**因此，同一页出现 30 ETF、75 股、990 股、11 条候选、14 条持久化记录，并不自动构成矛盾。先辨认对象、来源和时间，再比较。**

## 4. 六种“保存/完成”状态必须分开

| 对象 | 可以保存什么 | 是否足以证明有效 |
|---|---|---|
| 模板 | 通用算法与默认参数 | 不足 |
| 草案 | 想尝试的公式、参数、日期 | 不足 |
| 即时预览 | 按当前表单计算的一次结果 | 不足；历史已经可见 |
| 本地实验 | 浏览器 localStorage 中的摘要 | 不足；也不是集群正式归档 |
| 正式不可变实验 | 数据、规格、代码、模型或结果与校验清单 | 可复现，但仍需检查研究设计 |
| 已注册策略版本 | 完整行为规格和血缘关系 | 是治理对象，仍不等于获准运行 |

例如，Qlib 显示 COMPLETE，含义是固定运行已归档；同时显示非 PIT 和不可晋级并不矛盾。

## 5. 一张卡片应该怎么读

建议固定读法：

1. **对象**：它研究的是哪个因子、模型、策略？
2. **输入**：多少标的、哪个数据版本、什么复权、哪个时间窗口？
3. **时序**：信号何时可知，订单何时执行，标签何时成熟？
4. **假设**：仓位、成本、容量、基准、停牌与涨跌停怎样处理？
5. **结果**：收益、回撤、预测、统计显著性和稳定性是否一致？
6. **身份与限制**：是否正式归档？是否历史窗口已看过？哪些关键输入未认证？

不要从“收益最高”开始读。两张卡片只要股票池、区间或成本不同，就不能直接排出优劣。

## 6. 图形的基础读法

### 6.1 净值曲线

初始净值常归一为 1。净值 2.11 约表示累计收益 111%，并不是当天涨了 111%。曲线的斜率表现增长速度，但图的纵轴截断会放大视觉变化。

### 6.2 基准曲线

用来回答同一时期“不使用这个主动信号”会怎样。沪深 300、样本池等权、同入场退出时钟的无条件组合，是不同基准。

### 6.3 回撤曲线

表示距离此前资金峰值跌了多少，一般不大于 0。策略可以长期上涨，同时经历很深回撤。回撤的深度和恢复时间都重要。

### 6.4 超额曲线

当前一些图用策略归一净值减基准净值。它与“策略/基准净值之比减一”、每日主动收益累积不是同一计算。读图时要认准代码采用哪一种。

### 6.5 双纵轴

Qlib 图左轴是净值，右轴是回撤百分比。回撤线与净值线在屏幕上的交点没有经济含义，因为单位不同。

## 7. 状态、颜色与原因码

绿色多表示某项工程或检验条件通过，红色表示失败，橙色表示限制或等待；每个颜色都只适用于它旁边那一项。

NOT_ELIGIBLE 表示当前不能晋级；NONE 表示没有被分配 Champion/Challenger 等角色；AD_HOC_UNREGISTERED 表示临时研究身份尚未注册。页面顶栏的“模拟交易”不能单独证明某个候选正在 PAPER 运行。

原因码如 CURRENT_UNIVERSE_SURVIVORSHIP_BIAS，表达具体阻断项，不是系统异常。NO_PAPER_OR_SHADOW_SESSIONS 表示缺少相应运行证据，和回测是否完成是两件事。

## 8. 这一章的自测

“文件哈希全部验证通过、历史净值上涨、页面显示 COMPLETE，所以可以进入模拟盘。”这句话错在哪里？

答案：三项只能分别说明身份一致、某组假设下表现和工程完成；仍需数据时点、样本外独立性、成交可行性、完整注册、前向证据与运行准备等检查。具体门槛见第 06、09 章。
