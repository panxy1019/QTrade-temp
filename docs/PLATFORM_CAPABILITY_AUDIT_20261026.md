### 尚需接通的日常更新环节

Qlib目前固定使用 `daily-liquid-990-20261023`。后台行情更新不等于新交易日已经
通过Qlib适配，也不等于模型已重新训练。后续需要明确接通：

原始日线增量 → 金额与复权适配 → 覆盖/交易日/口径验收 → 新Qlib数据版本 →
可选的预定重训任务 → 新实验归档与发布。

新数据可以成为新任务的输入；旧实验继续保留原数据、来源和结果。网页每15秒查询
任务目录，也不代表集群每15秒产生新数据；公开发布与GitHub CDN还有缓存时延。

## 2. 因子、模型和策略分别是什么

当前正式Qlib链路是：

`Alpha158特征 → Ridge/LightGBM预测得分 → TopkDropout选股与持仓 → 成本/约束回测`。

- 因子或特征是输入，例如过去20日收益、波动、价量关系。
- 模型把多个输入转换为预期收益或排序得分。
- 组合规则根据得分决定买哪些、持多少、何时替换，再经过交易与风险约束。
- 完整策略还包括股票池、调仓时点、仓位、成本、成交和退出规则。

因此，当前两种预测模型使用同一种主要组合规则，并不等于接通了两个不同投资
策略家族。Alpha158也不意味着已经验证了158个独立、有效、可交易的alpha。

## 5. 后续交付安排

### 第一批：数据可信度与因子评价并行，均为P0

数据线的验收交付：

1. 修复旧分钟检查点复用：哈希、证券身份、起止日、交易会话和时间网格共同验收；
   不合格进入隔离/重采清单。报告分别显示已请求、已下载、覆盖合格、来源已对账数量。
2. 继续990股状态回填，保留失败与原始接收时间；推进官方退市身份对应的行情试采，
   查清上市/摘牌/最后交易日语义。当前回填不填造历史available_at。
3. 建立日线增量到新Qlib版本的流程；失败继续显示旧版本及其截止日，不伪装成今天。
4. 将当前库存、最新合格研究版本、每个冻结实验三个时钟分别展示；保留发布/CDN延迟。

因子线的验收交付：

1. 在现有PriceFactorSpec和评价模块上扩展统一登记：factor_id、版本、公式、输入字段、
   频率、窗口、warmup、lag、可得时间规则、复权、缺失、预处理、代码和数据身份。
2. 先登记约20—30个有清楚含义的价量因子及Alpha158分组，不以因子数量作为验收标准。
   市值、行业、财务因子须等其时点输入可核验后加入，不能用今天分类回填历史做认证。
3. 网页能够选因子、数据版本、股票池、区间和标签，执行集群任务并保存独立报告。
4. 报告至少含覆盖与缺失、日/月/年IC和RankIC、分层单调性、换手、自相关、1/5/10/20
   交易日持有期诊断、分时期稳定性和与现有因子的相关性。重叠收益与序列相关需使用
   合适的统计处理；预处理只使用训练期允许的信息。
5. 分层多空差值仅作统计诊断，另以实际允许的组合、成本和成交约束判断可交易收益。

### 第二批：统一策略对照与验证，为P1

先形成五组可解释的信号基线，使用同一支持股票池、数据来源、Topk规则及成本：
动量、低波动、简单多因子排序、Ridge、LightGBM。沪深300等作为明确的外部基准。
此时控制变化的是信号或模型。研究权重、调仓频率等组合规则时另开对照轴，不能仍称
“纯模型增量”。

再逐步加入等权、风险约束权重、最大单股/行业权重及换手惩罚。行业和市值约束使用
有时点证据的输入，数据不足时只提供明确标注的诊断。

验证交付包括：

- 新Qlib任务支持有界滚动训练、验证、测试，保存每个窗口及汇总，标签边界隔离。
- 固定费用倍数、延迟和成交额容量压力；分别说明历史真实费率与研究成本近似。
- 保存每日持仓、委托、成交/拒绝原因、行业/风格暴露及收益归因。
- 登记所有候选与失败结果、限制搜索预算、固定外层测试；重复看过的历史不再称为
  新的未见样本。建立从真实未来日期开始、当时封存预测的前向观察。
- 复用现有策略注册/谱系模块，使因子版本→信号→组合→实验→策略候选能够追溯。

### 第三批：LLM受控研究与事件文本，为P2

[RD-Agent官方项目](https://github.com/microsoft/RD-Agent)提供基于Qlib的因子、模型
迭代及报告因子提取方向，可以借鉴候选产生与实现流程；项目宣传的收益不能直接
外推到我们的股票池或数据。

先让LLM按结构化合同产生少量价量因子候选，由隔离计算环境执行，进入同一独立
评价与策略对照流程。限制字段、算子、候选数、计算时间和API预算，保留失败结果。
已有词法/表达式和任务允许列表应继续复用，不开放任意网页代码执行。

公告方向先做一个明确事件的小样本：原文、证券映射、公告发布时间、实际抓取时间、
更正版本、去重、事件分类、预期交易时点一并保存。LLM负责结构化，时间与回测合同
由确定性代码校验。须记录模型、提示词及版本，并考虑预训练模型对历史事件的知识
泄漏；最终效果以事先封存的前向数据验证。

因子登记、独立评价和简单策略可以同步建设，无需先攒齐数百个因子才做策略。
PIT与交易约束保持并行最高优先级；LLM增加候选速度，不能代替数据与实验有效性。

## 6. 能力完成的判据

能够新增一个因子，明确其时点输入，得到独立评价，与已有因子判断重复，再放入
固定策略做成本后对照，并完整重现和追溯结果，才算具备基础因子研发平台。
目前已打通其中的模型任务与归档链路，其他部分仍需按上面批次补齐。

所有研究保持 NOT_ELIGIBLE，实际晋级须另行通过数据、风险及执行验收；
`LIVE_TRADING_ENABLED=false`。策略仍遵守 portfolio → risk → OMS → execution → gateway。
