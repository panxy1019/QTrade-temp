## 已经证伪，不能上线的方案

1. 独立aux对象图与元数据预传：本地六组默认/`push.negotiate=true` 对照，
   即使sender有aux ref，wire均仍含9对象、152543 bytes和全部5个已预传blob。
   原始wire PACK与接收端pack逐字节相同，排除了thin补base造成的误计数。
   不给生产增加该配置。
2. non-delta对象缓存：节省约0.6秒生成时间，却增加约23.3MB wire，不能为
   节省NFS随机读而忽略实际传输量。只保留本地原子安装器的17项边界测试；
   该实现强制fixture sentinel，无生产入口，不准备生产安装。
3. metadata-only base +增量bundle：本地 `verify=0/unbundle=0` 仍缺4/6个
   当前blob、fsck失败。完整浅base才通过断网恢复。无delta不能补齐原来被
   排除的base blob；只核bundle头不构成数据完整验收。初始归档遗漏空目录
   的夹具失败也保留，不能挪用修正后结果覆盖。

所有Git包均由已提交的公共数据仓库读取，写入新operator目录；没有向生产
objects/refs/index/config写入，没有删除loose对象、改变MIDX、重启服务或
执行第二次人工主分支push。文件系统缓存未清空，不称为冷OS缓存性能保证。

## 单次冷恢复拟议边界，尚待批准

当前正常90秒合同不适合被不断扩大。若采用一次独立冷恢复，建议新建明确的
180秒冷操作预算，普通publisher仍90秒、导出仍45秒。它是待批准方案，不因
A/B/C已批准就宣称本次预算例外已获批准，也不作为原失败intent的重试。

新方案必须先具备冻结目标、真实导出SUCCESS45收据、全部当前分片与来源
校验、固定公开远端、旧INTENT/UNCERTAIN跨绑定、无客户端残留证明及新鲜
只读远端对账。发送只允许一次non-force操作，任何不确定结果保留，不自动
再次发送。原生Git具有自身广告旧OID的ref更新检查；事前ls与send不是同一
事务，不将其描述为独立的expected-base跨事务锁。

执行后分别检查ACK/实际remote提交、固定公开索引及API、普通publisher的
后续自然90秒轮次及新鲜度。辅助交付不代替自主持续发布；若依然失败仍为
失败，不提高日常预算、不截断数据、不改变当前模型或PAPER。

本轮源与证据另归档到同目录evidence；大pack本体仅留隔离操作目录，以其
SHA256、严格验证、完整object-list和原始小报告作引用，不混入应用源码Git。
