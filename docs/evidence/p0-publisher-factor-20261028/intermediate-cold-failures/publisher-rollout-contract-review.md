## Recommended reviewable handover: one TERM, natural exit, existing automatic restart

The existing old publisher's SIGTERM handler sets an Event and lets the current cycle finish before exiting. A45-second export followed by ordinary90-second Git work can exceed stopwait110. Sending Supervisor `stopProcess` while busy therefore risks escalation even though the signal is TERM. A main-thread futex wait alone is insufficient: executor waits can also use futexes. Fresh cycle-completion logs plus an actual Python call-site at `stop.wait` can identify a likely idle opportunity, but a check-then-signal observation still races the next60-second cycle. Do not promote those clues to a guaranteed idle proof.

The following alternative avoids forced escalation without changing45/512MB/cache128MB/Git90/stopwait110 or touching another owner:

1. **Prerequisites before any wrapper mutation:** the final committed source, independent code review, exact Linux source/import validation, current-freeze cold/warm success and complete lineage proof all pass. In an isolated instance of the **same captured Go Supervisor binary/build**, verify that its existing `autorestart=true` restarts a normally exiting/TERM-drained child once and that no stopProcess escalation timer is armed by a direct signal. Do not assume standard Python Supervisor semantics. Also verify the actual private wrapper is a one-shot launcher/exec and is not periodically reread by the running process; preserve the entire old release.
2. Archive a new durable attempt with old PID294214/start_ticks, command/cwd, selected environment fields (LIVE/PYTHONPATH only), config/wrapper hashes, release/test/benchmark/audit identities, current publication checkpoints and all non-publisher control/fingerprint snapshots. Recheck the old process identity and config bytes against that record. An absent or changed owner blocks; it does not authorize substitution.
3. After syntax/import checks, atomically install only the reviewed wrapper path so its next launch uses the exact new immutable release; fsync the wrapper's parent directory and archive the installed hash. The current process continues using its old cwd/imported modules. This preinstalls the new target **after all gates pass**, so an unrelated old-process exit cannot launch an unvalidated candidate.
4. Open a Linux pidfd for the old owner, recheck its /proc start_ticks/module/cwd against the frozen identity, durably record the signal intent, then send **one SIGTERM to that main process through the pidfd**. Do not signal its process group, invoke stopProcess, or signal Git/SSH descendants. The existing handler drains the cycle; existing Git90/cleanup and exporter contracts stay in effect. Close the pidfd and record the delivery result. If pidfds are unavailable, do not silently downgrade to an unchecked numeric-PID signal; prepare and review an identity-safe alternative.
5. Observe natural old-owner exit and its Supervisor log exit disposition, owned Git session/descendant cleanup, and existing autorestart launching the new wrapper. A reviewer/operator observation deadline can return **DRAIN_PENDING**, but it must not kill the process, extend runtime limits, re-send TERM, invoke stop/start, reset the attempt, or replay an already consumed action. An intent without a confirmed delivery receipt is an uncertain phase, not permission to send again. A crash/interruption resumes by readonly phase inspection.
