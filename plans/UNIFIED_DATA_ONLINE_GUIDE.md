# QTrade 下一阶段开发：统一1500证券数据平台与Qlib Online Serving全链路

## 一、项目背景与总体目标

当前 QTrade 已经具有以下能力：

- Vercel 网页：`https://q-trade-temp.vercel.app/`
- Qlib 研究入口：`https://q-trade-temp.vercel.app/#/research`
- 研究账户权限及受控配置
- 私有 Git + SQLite 持久化研究任务队列
- 集群 Supervisor 数据采集与维护服务
- Parquet、数据 manifest、checksum 与不可变实验归档
- Qlib 0.9.7 + Python 3.11 + MLflow
- Alpha158、Ridge、LightGBM、TopkDropout 日频训练和回测
- 模型、预测、持仓与实验结果归档
- 网页研究任务提交、结果展示及任务状态监控

但当前存在的问题是：

1. 数据采集仍然按 ETF30、盘中75股、长期日线1000股、长期分钟400股等历史工程任务划分。
2. 1000股长期日线原料没有完成统一每日增量更新到Qlib的闭环。
3. 五分钟长期扩容尚未完成，旧检查点存在跳过新质量验收的问题。
4. Qlib使用冻结数据版本，新交易日不能自动完成适配、预测及发布。
5. 已保存模型，但没有完整验收恢复模型与处理器、每日自动预测和预测封存。
6. 滚动重训、模型激活、OnlineManager等生命周期能力尚未接入正式网页。
7. 部分历史股票池、ST、退市、停复牌及公司行为数据仍存在PIT限制。

### 本轮总体目标

将 QTrade 升级成统一量化研究数据平台：

**统一证券池 → 日线/五分钟连续采集 → 数据质量验收 → Qlib增量数据版本 → 每日自动预测 → 可选自动滚动训练 → 模型验证与激活 → 实验和前向信号归档 → 网页管理与展示。**

保留现有架构，不另建网站，不重写Qlib回测引擎，不替换已经稳定工作的任务队列。

所有工作分阶段执行、独立验收。

## 三、第二阶段：统一证券主表与1500证券目标池

### 3.1 统一股票池

取消ETF30、75股、1000股、400股作为长期独立业务数据池的设计，迁移到统一的证券主表和版本化研究证券池。

目标活跃观察规模约1500只独立证券，不硬编码数量。

首先合并现有证券清单，统一代码和交易所标识，去重并输出来源映射。

统一主表至少包含：

- `instrument_id`
- `exchange`
- `security_type`
- `listing_date`
- `delisting_date`
- `status`
- `source`
- `observed_at`
- `valid_from`
- `valid_to`
- `available_at`（仅在来源可证明时填写）
- `universe_version`
- `data_quality_status`

支持股票、ETF和历史退市证券。

历史证券身份保留，不因当前退市而删除历史研究记录。

不得把当前流动性筛选的1500只证券回填为十年前的真实历史可选股票池。

必须区分：

1. 当前观察证券池。
2. 当时可知的历史研究证券池。
3. 已经停牌、退市或数据不可用的历史证券。

### 3.2 统一采集管理

为同一证券统一管理不同频率的数据。

第一版支持：

- `day`
- `5min`

所有目标活跃证券默认纳入两种频率的采集计划，但需要允许按实际来源覆盖记录无法获取的频率。

不能因为某个证券缺少五分钟历史而自动排除其合格日线。

## 四、第三阶段：统一日线和五分钟持续采集

### 4.1 日线数据

目标为约1500只证券，尽可能取得过去10年真实日线数据，并在每个正常交易日持续增量。

要求：

1. 优先复用已有已验证历史数据。
2. 增量采集新交易日，不全量重下十年历史。
3. 保存供应商原始响应和SHA256。
4. 校验OHLCV、成交额、日期和证券身份。
5. 检查停牌、上市、退市和公司行为。
6. 不覆盖旧数据版本。
7. 数据来源异常时进行受限重试，并保留最后成功状态。
8. 验收后生成新的合格日线版本。
9. 通过版本事件触发Qlib下游任务。

### 4.2 五分钟数据

目标为同一批约1500只证券，持续采集五分钟数据，并逐步回补最多10年的历史。

要求：

1. 复用已有Sina和BaoStock采集能力。
2. 对供应商频率、复权口径和真实可用历史范围进行审计。
3. 不假设免费供应商一定可以提供十年五分钟数据。
4. 先建立数据源覆盖和下载吞吐报告。
5. 历史回补与当天新行情采集独立调度。
6. 新行情采集优先于低优先级历史回补。
7. 每根五分钟Bar必须有明确的交易时钟与完成状态。
8. 按交易会话、午休和时间网格验收。
9. 不补造缺失K线。
10. 遵守已经发现的BaoStock匿名会话并发限制。
11. 允许断点续传与逐证券失败重试。
12. 保留所有旧Parquet与失败记录。

修复旧checkpoint复用缺陷：不得只通过文件哈希就跳过新的覆盖验收。必须重新检查起止日期、有效会话、时间网格及质量规则。

输出分别表示请求、下载、解析、校验、来源对账和正式发布的真实进度。

### 4.3 十年数据验收

十年是目标覆盖长度，而不是要求所有证券必须拥有十年历史才能进入系统。

新上市证券按实际上市日期计算有效覆盖；退市证券按真实历史有效区间保存。

对于无法获取的历史五分钟数据，记录缺口、来源和原因，不允许虚构覆盖率。

历史分钟数据源未通过验证时，不得为了达到目标数量拼接复权口径不一致的数据。

## 五、第四阶段：P0数据可信度

统一数据质量规则，并建立可在网页查询的质量审计。

至少检查：

- 证券身份与历史资格
- 真实上市和退市时间
- 历史交易日历
- 日内五分钟网格
- OHLC价格关系
- 成交量和成交额
- 分红及复权因子
- 历史ST状态
- 停复牌状态
- 涨跌停与可交易限制
- 数据来源及获取时间
- checksum和manifest
- PIT可认证程度

将质量状态分为：

- 采集成功但尚未验证
- 内容与覆盖验证通过
- 来源对账通过
- 历史时点信息已认证
- 有限制可用于研究
- 不合格或隔离

不得把来源对账通过等同于完整PIT认证。

对于未取得权威历史状态的证券，只能标注相应限制，不能从缺失价格推断停牌原因，也不能伪造`available_at`。

保留旧数据身份和已有实验结果。

## 六、第五阶段：统一数据湖与Qlib增量数据版本

建立统一数据目录，包含：

1. 供应商原始数据层。
2. 统一标准化Parquet层。
3. Qlib Provider输入层。
4. 数据版本manifest与质量报告。

所有证券共享统一主表，按频率、证券和时间区间进行分区。

日线和五分钟拥有独立的版本、覆盖状态和更新时间。

必须支持：

- 增量写入
- 原子发布
- 历史版本复现
- 数据hash与来源谱系
- 已完成数据与正在写入数据隔离
- 旧版本不可变
- 数据版本回退
- 同一批次幂等执行
- 失败恢复与重试

避免每天复制全部历史分钟数据造成空间放大。

Qlib正式读取已经验证的数据版本，不读取仍在写入中的目录。

日线和五分钟可以共享一个逻辑数据平台，但必须分别验收Qlib Provider的频率配置、日历、表达式和窗口语义。

### 数据版本自动更新

当新的完整日线验收通过：

- 发布新日频Qlib版本。
- 记录已就绪证券数量和真实覆盖。
- 更新当前可用数据指针。
- 通知每日预测任务。
- 根据配置决定是否创建滚动训练任务。

当新的完整五分钟数据验收通过：

- 发布五分钟版本或增量版本信息。
- 更新分钟行情展示。
- 仅通知依赖对应频率的研究任务。

不能把仅用于Qlib回测边界的未来日历占位日当成真实行情日期。

## 七、第六阶段：Qlib每日预测和自动训练

沿用当前Qlib 0.9.7环境，先进行官方组件接口与兼容性审计。

优先复用：

- `OnlineManager`
- `OnlineStrategy`
- `OnlineToolR`
- `PredUpdater`
- `RollingGen`
- `RollingStrategy`
- `TrainerR`
- `DatasetH`
- `DataHandlerLP`
- `LGBModel`
- `TopkDropoutStrategy`
- Qlib Recorder及MLflow

注意不是所有组件都必须同时启用。根据实际任务逐阶段接入，不复制官方框架内部的训练和回测算法。

### 7.1 模型恢复

首先验证当前已归档模型能否跨进程恢复。

检查：

- `model.pkl`
- DataHandler及其训练期拟合的处理器
- 特征列名与顺序
- 模型参数
- Qlib数据版本
- 原始预测结果
- Recorder身份
- 原代码及依赖环境

如果原始归档缺少完整预处理器，不能默认为已具备可靠在线恢复能力。

必须先完成恢复一致性测试，再发布在线模型版本。

### 7.2 每日自动预测

提供独立的`AUTO_PREDICT`能力。

当新数据版本验收通过时：

1. 获取当前ACTIVE模型。
2. 加载冻结的模型与预处理器。
3. 计算最新有效特征。
4. 生成预测分数。
5. 检查证券覆盖和时间语义。
6. 保存不可变预测快照。
7. 发布结果摘要到QTrade。
8. 等未来收益实际发生后独立评价。

不得覆盖旧实验中的预测文件。

每份信号必须绑定模型、数据、股票池、信号生成时间和预期执行时间。

如果新数据未通过验收，不生成伪装成当日的新信号。

### 7.3 自动重训

新增受控训练政策：

- OFF：不自动重新训练。
- DAILY：每个合格交易日尝试创建候选重训任务。
- WEEKLY：每约5个交易会话触发。
- MONTHLY：每约20个交易会话触发。
- CUSTOM：允许列表内配置明确的交易会话间隔。

所有模式均受数据就绪、标签成熟、任务互斥、资源预算及模型验证限制。

使用Qlib RollingGen生成训练、验证和测试时间窗口；执行使用现有QTrade任务队列及Qlib TrainerR或经验证的兼容适配。

必须确保训练标签不会读取未来未成熟收益。

每次训练产生新的不可变实验及模型版本，不覆盖原模型。

### 7.4 模型生命周期

建立：

- TRAINED
- VALIDATING
- VALIDATED
- STAGED
- ACTIVE
- FAILED
- RETIRED

当前有效模型与候选模型分开管理。

第一阶段默认人工批准候选模型激活；后续允许定义严格的自动激活规则，但不得根据反复查看过的测试集无限优化。

激活过程需具备幂等、原子切换、历史记录和失败回滚。

允许模型训练失败时继续使用上一版已验收模型进行预测，但仅在当天数据本身满足输入要求时才能发布新信号。

Qlib原生OnlineToolR/Recorder标签不得直接替代QTrade的完整发布与审计事务。

## 八、第七阶段：Qlib策略与前向PAPER研究

保留当前Ridge和LightGBM的TopkDropout基线。

增加：

- 单因子动量
- 单因子反转
- 低波动率
- 简单多因子组合
- 等权基准
- ETF趋势轮动（在统一研究合同下）

信号与组合构建逻辑必须分离。

同一个预测信号可在不同受控组合规则下比较，但应当明确标记实验变化轴。

每日预测生成后，根据当前组合状态、TopK、换手和成交约束生成目标仓位。

每日目标仓位进入不可变的PAPER/SHADOW研究记录，不调用真实券商网关。

保留实际历史收益与前向观察结果的明确区别。

不能将每日新数据追加到已完成旧实验的净值曲线上，并将其伪装为当时已经生成的真实前向预测。

## 十、第九阶段：调度、资源与失败恢复

继续保留现有Supervisor、Git+SQLite队列和受控研究工作器。

不要在未证明必要性之前引入新的RayCluster、MongoDB任务系统、Kubernetes集群或其他复杂基础设施。

要求：

1. 采集、数据发布、预测、训练任务分别可见。
2. 日常行情采集优先于历史回补。
3. 每日预测优先于低优先级重训。
4. 大型训练和历史分钟补齐要有资源预算。
5. 相同证券、频率、日期及数据版本的更新需要去重。
6. 任务失败后保留失败状态和证据。
7. 不允许多个写入者同时修改同一数据版本。
8. 服务重启后能够恢复计划和任务状态。
9. 模型激活失败不能破坏当前模型。
10. 持久卷可用空间低于已有安全阈值时暂停新增大量历史写入。

若现有13 vCPU和60 GiB内存无法同时承担1500证券的历史补齐和Qlib训练，应先测量吞吐、内存和I/O，再决定是否增加机器资源。

## 十一、验收要求

分阶段测试并提供真实证据。

### A. 数据验收

- 同一证券身份正确映射日线和五分钟。
- 数据增量与原始供应商记录对账。
- 数据版本可重现且旧版本不改变。
- 新上市、停牌和退市证券处理正确。
- 长分钟旧检查点经过完整复验。
- 新日线可按交易日自动进入Qlib。
- 缺失或异常数据有明确状态和阻断规则。

### B. 模型验收

- 模型及预处理器跨进程恢复。
- 与原冻结实验预测一致。
- 新数据到达后自动产生正确日期的预测。
- 自动重训仅在满足条件时触发。
- 未来收益标签不会提前进入训练。

- 已完成历史实验不被修改。

### C. 网页验收

## 十二、交付方式和实施顺序

不要一次性完成全部内容后才检查。

按以下顺序实施：

**Phase A：现状审计与统一证券池**

交付系统架构、去重后的目标证券池、现有数据源能力和覆盖缺口报告。

**Phase B：持续数据采集与P0质量治理**

交付统一日线与五分钟增量通道、长分钟检查点修复、历史回补计划和质量报告。

**Phase C：自动Qlib数据版本与固定模型每日预测**

交付新数据版本发布、跨进程模型恢复、每日不可变预测及网页展示。

**Phase D：滚动训练与OnlineManager**

交付训练周期配置、RollingGen、Trainer适配、在线模型版本、激活和失败恢复。

**Phase E：因子、策略、PAPER与网页完整集成**

交付统一基础因子、策略基线、每日研究组合及前向观察。

每阶段都需要：

- 代码修改
- 单元与集成测试
- 集群真实运行验收
- 网页生产验收
- 数据及结果身份记录
- 已知限制清单
- 面向维护者的Markdown文档

本轮不得覆盖旧冻结数据或现有模型；不得把历史数据补齐、自动预测和自动重训混为同一任务。

如果实际数据源无法提供十年五分钟历史，应如实交付已认证覆盖和缺口报告，而不是宣称十年数据已完成。

最终目标是持续可运行、可观察、可重现、可恢复的QTrade+Qlib统一量化研究平台，而不是仅在网页新增相应菜单。
